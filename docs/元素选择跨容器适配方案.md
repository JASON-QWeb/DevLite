# 元素选择跨容器适配：实现与验收

状态：已实现，真实浏览器回归通过。要求 Chrome 119+。这里记录元素操作的支持范围，不把元素可选等同于子应用网络、console、性能采集已完整适配。

## 1. 解决的问题

原来的选择器只在顶层 document 工作，使用 event.target 和普通 CSS selector。微前端的事件可能被重定向到组件宿主，iframe 的事件也不会冒泡到父文档，所以只修改点击处理无法打通编辑、撤销、导出和更新校验。

实现按真实 DOM 结构接入 Document、Shadow Root 和 iframe，不为每个框架单独维护适配器。无界的 JS iframe 与可见 DOM 所在文档可能不同，实际操作以元素的渲染文档为准。[无界架构说明](https://wujie-micro.github.io/doc/guide/)

## 2. 使用方式与边界

1. 安装或更新扩展后刷新目标页面。
2. 打开 DevLite，开始选择，直接点击子应用内部的元素。
3. 子文档在本地执行操作，主页面只显示一份编辑器；可以继续选择父级。
4. 选中全屏 iframe 内部元素时会退出该 iframe 的全屏，显示主编辑器。
5. 导出带有目标文档 URL、iframe 宿主路径、Shadow Root 路径和局部元素地址，便于区分不同应用中相同的 id。

| 场景 | 当前处理 |
| --- | --- |
| 普通 HTML、Vue/React 渲染结果 | 支持实际 DOM；框架重新渲染可能覆盖临时修改 |
| 开放、封闭、多层 Shadow Root | 按事件路径与根内命中检测选择，按根保存地址 |
| slot / Teleport / Portal | 定位按 DOM 所有权，高亮与父级导航按显示的组合树；不推断无法证明的业务归属 |
| 同源、跨域 iframe，任意交替嵌套 | 注入成功时在所属文档操作，按 documentId 路由 |
| about:blank、srcdoc、blob、data、sandbox | 遵循浏览器关联来源和站点权限规则；本次夹具的注入与操作均通过 |
| 受限 URL、无法注入的 frame | 不绕过浏览器限制；可选外层 iframe 时提示子文档未连接，外层容器仍可编辑 |
| SVG path、image、svg 容器、foreignObject 内 HTML | 精确选取，根据节点能力启用样式、图片、图标或文本操作 |
| SVG use、Canvas、WebGL、伪元素、原生控件内部 | 选择宿主；不承诺不存在或不可访问的内部 DOM 可独立编辑 |
| 业务 input / textarea / select、现有富文本编辑器 | 保留选择、样式和描述需求，不直接改业务值 |
| dialog、popover、全屏 | 使用浏览器 Popover 顶层显示；模态对话框内调整面板挂载位置，避免 inert 背景 |
| CSS zoom、滚动、尺寸变化、visualViewport | 在目标文档内绘制，多行元素按 client rects 绘制；旋转元素仍是包围框 |
| 子应用卸载、文档导航、虚拟列表复用 | 使旧引用失效，不把缺席误判为删除修复成功 |

Chrome 的 `openOrClosedShadowRoot` 是扩展原生能力；普通网页 JS 的 composedPath 不会暴露封闭根内部节点。这里没有永久改写页面 attachShadow，也没有引入调试器权限。[Chrome DOM API](https://developer.chrome.com/docs/extensions/reference/api/dom)、[事件路径说明](https://developer.mozilla.org/en-US/docs/Web/API/Event/composedPath)

## 3. 架构与主要模块

```text
主页面 content.ts：唯一编辑器、记录面板、图片裁剪入口
                    ↕ 可序列化摘要与命令
background/frameRegistry.ts：文档登记、会话状态、定向路由
                    ↕ documentId + requestId
子页面 frame.ts + ElementExecutor：本地选取、编辑、高亮、撤销
                    ↕
共享 DOM 上下文、元素地址、根登记、原有编辑和校验模块
```

| 模块 | 职责 |
| --- | --- |
| `src/frame.ts` | 全 frame 的轻量入口、握手、全局选择状态、本地高亮、生命周期 |
| `src/background/frameRegistry.ts` | 真实 sender 身份、在线文档登记、选择会话串行化、命令路由 |
| `src/content/elementExecutor.ts` | 子文档复用现有样式、文字、图片、图标、删除和校验实现 |
| `src/content/domContext.ts` | 跨 window 节点判断、实际文档、封闭根访问、事件命中、组合树、浮层缩放 |
| `src/content/elementAddress.ts` | 逐根地址、唯一匹配、指纹与结构化失效状态 |
| `src/content/rootRegistry.ts` | 分批发现根、变更版本、操作范围过滤、滚动监听和卸载清理 |
| `src/content/changeManager.ts` | 原始 inline 声明、原节点和属性快照、撤销与恢复 |
| `src/content/domLocator.ts` | 当前根与关联根的 CSS 候选、继承线索和不可读来源标记 |
| `src/content/styleVerification.ts` | 目标文档内校验，排除预览 inline 值，CSSOM 复查 |
| `src/content.ts` | 保留主页面 UI 编排，接收子文档摘要并防止过期操作重新打开面板 |

顶层和子文档共用编辑、地址与校验模块。没有另建框架插件注册表，也没有重写整个主页面控制器。面板、裁剪 UI、网络和诊断模块不随轻量执行器复制到每个沙箱。

静态执行器在 document_start 注入，设置 all_frames、match_about_blank 和 match_origin_as_fallback；顶层面板仍在 document_idle 加载。已有页面的补注入幂等，遇到受限子文档时不阻断顶层工具启动。frame.js 与其他内容脚本一起生成独立经典脚本并经过 smoke 检查。[Chrome 内容脚本文档](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts)

## 4. 地址、消息与生命周期

持久地址分为两部分：

- `context.framePath`：从顶层开始的 iframe 宿主地址序列。每个宿主地址本身可包含 Shadow Root 路径。
- `address`：当前文档中的 `version: 1`、`shadowPath`、局部 selector 和指纹。

运行中的 documentId 与 change.id 用于执行路由，不能用 frameId 代替文档身份。导航后编辑旧文档的命令会失败；校验、撤销和释放记录需要恢复文档时，只接受 URL 与完整 framePath 唯一匹配的在线上下文。新记录的 DOM 撤销还要求保留原始节点快照，不能通过地址匹配假装恢复框架状态。

解析器区分 resolved、document-unavailable、root-unavailable、target-missing、ambiguous、stale-handle、unsupported。旧记录没有地址时只在原有顶层范围查找，不扩散搜索其他应用。写入前检查连接状态与标签、命名空间、稳定属性、有限文本指纹。指纹是保守的身份线索，不能识别页面未暴露的业务主键。

后台以 `sender.tab.id / frameId / documentId` 为身份依据。子文档只能使用元素协议；其他修改顶层会话、页面上下文与诊断数据的入口拒绝子文档调用。子文档更新记录时检查既有记录归属；过期记录不会覆盖更新的记录。主页面命令串行发送，执行器缓存最近 64 个 requestId 的结果，避免重复删除。

父子文档通过 WindowProxy 对应的 iframe 宿主建立路径，关联信息只用于路径发现，不替代扩展 sender 身份。重新选择时更新宿主路径。未就绪时的关联重试有界，未能建立路径时不猜测跨导航目标。

worker 重启后使用原生 scripting 清点在线上下文，导航替换与卸载的登记会清理。进入 BFCache 暂停根监听，pageshow 恢复握手。新 frame 会加入正在进行的选择会话。

真实无界降级模式还验证了 document.open 的边界：它会清空 Document/Window 的 DOM 事件监听，执行器因此在选择会话同步时重新绑定；使用 AbortController 保证不重复注册。[Document.open 行为](https://developer.mozilla.org/en-US/docs/Web/API/Document/open)

## 5. 编辑、撤销和校验

样式同时保存 computed 基线与原始 inline 值、priority。撤销移除原来不存在的 inline 声明，并恢复原始 !important，不把 computed 值写回页面冒充原状态。

文字编辑使用目标 document 的 Selection、Range 和焦点，保留中文 composition 与纯文本粘贴处理。图片修改支持 img、picture/source、SVG image 和背景图；撤销同时恢复受影响的 source，SVG 属性保留命名空间。异步文件、裁剪、在线图标及远程操作结果均检查原选中项，避免写入新选中的对象。

删除与文本/图标替换保留原节点、子节点、属性、原父节点与相邻锚点。同一文档撤销优先使用原节点，因此测试中的既有监听器得以保留；父容器消失或被业务复用时拒绝恢复。跨导航丢失快照的新记录不回退到 outerHTML 重建。旧版本静态记录仍保留兼容恢复路径。

校验按元素所在文档和根记录更新版本。对待校验项每 2 秒有界复查，以覆盖 insertRule、replaceSync 等不触发 DOM MutationObserver 的 CSSOM 更新。CSS 值在实际目标环境中同步归一化，临时排除预览声明，随后恢复原始 style 属性；相对单位、继承和 CSS 变量因此使用子应用自身环境。

删除记录一律保留人工确认：节点缺席也可能来自路由、虚拟列表或应用卸载，仅凭浏览器 DOM 无法证明源码已经删除。原节点上的文本/结构预览也不会直接作为源码修复成功的证据。

CSS 采集读取当前根的 styleSheets、adoptedStyleSheets，并提供 :host、slot、part 和继承上下文线索。受预算限制最多保留 16 条候选，遍历最多 2500 条规则；不可读样式表记录来源但不阻断选取。这是定位候选，不是浏览器完整的最终层叠结论。

## 6. 性能和清理

- 初次与动态根发现按每批 300 个元素处理；选择活动期间每 2 秒发现晚挂载根。
- 高亮绘制按 requestAnimationFrame 合并，保留最多 80 个片段。
- 根卸载时断开 observer、滚动与 slot 监听；保活重新挂载可再次注册。
- 退出选择后停止全量活动扫描；没有待验证记录时关闭相关复查。
- 未产生修改的临时选择和快照会清理；已修改记录保留撤销所需状态，直至撤销或归档。
- 父子路径重试、请求结果缓存、CSS 采集与根扫描均有明确边界。

压力夹具包含 20 个 frame、100 个 Shadow Root 和根内 20,000 个元素，并进行反复挂载与卸载。最终全量测试中选中响应为 69 ms，观察窗口内无长任务；回收检查中 DOM 节点从 3726 回落到 3119，监听器从 699 回落到 626。该结果只说明本机夹具表现，不是所有设备的性能承诺。后续运行的实际数值以 `output/qa/browser-results.json` 为准。

## 7. 验收与复现

```bash
npm ci
npm run test:all
```

`test:all` 包括构建、经典脚本/manifest smoke、原有单元测试及加载真实扩展的 Chrome QA。QA 使用临时用户目录，结束后清理；结果保存在 `output/qa/browser-results.json`，失败时保存截图。Chrome for Testing 版本为 153.0.8010.36，系统为 macOS；manifest 的最低版本为 119，未逐个复测 119 至 152 的所有浏览器版本。
